# GoreeCloud Home — Competitive Objectives

GoreeCloud Home is not intended to clone Home Assistant, Google Home or Apple Home. They are comparison points for user outcomes.

## Objectives

1. **Home Assistant-class depth with simpler defaults** — support sophisticated local automation, interoperability and diagnostics while keeping common household control approachable.
2. **Google Home-class discoverability and household ease** — make onboarding, rooms, favorites, routines and shared household use understandable without requiring cloud dependence.
3. **Apple Home-class local trust and cohesive experience** — prioritize local execution, clear permissions and polished platform-native interaction while avoiding ecosystem lock-in.
4. **Broader portability** — documented backup, restore, export and migration for user-owned Home configuration and data.
5. **Protocol neutrality** — Matter/Thread first, with Zigbee, Z-Wave, MQTT, BLE and local integrations behind GoreeCloud capability contracts.
6. **Explicit state truth** — never represent a requested command as confirmed device state until the device/adapter reports it.
7. **Offline automation authority** — local automation must not depend on GoreeCloud Mesh, remote APIs or Internet connectivity.
8. **GoreeCloud platform cohesion** — integrate Identity, Wardveil Security, Privacy Shield, Everkeep, Manager, Mesh and Glaze UI substantively rather than through branding alone.

## Non-objectives

- Copying another smart-home application's architecture or UI.
- Requiring a GoreeCloud cloud subscription for basic local control.
- Treating unsupported proprietary cloud APIs as the permanent core integration strategy.
- Claiming protocol compatibility without real interoperability evidence.
- Exposing locks, alarms, doors, cameras or comparable privileged actions through unauthenticated control surfaces.
